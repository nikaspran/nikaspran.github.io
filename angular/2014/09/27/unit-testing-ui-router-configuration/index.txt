11:T5e00,<h3 id="why">Why?</h3>
<p>Angular app configuration is code, so one could argue there is no real
reason not to test it. If you misconfigure your application, it's
no less threatening than a bug in some controller or service.</p>
<p>End-to-end testing can (and should) be used to verify major functionality.
It is, however, rather more difficult to write and maintain. In contrast,
unit tests let you check the details at impressive speeds.</p>
<p>Unit testing the <code>.config()</code> blocks in your Angular app seems a daunting
task at first. You can't easily access the providers (tests run after
the config phase is over) and there is usually a lot of stuff that gets
bootstrapped along even for the tiniest of tests.</p>
<p>There is however a rather painless way of testing at least the routing of your
app, which is usually where a lot of the important logic happens. In this post,
we'll be looking into how you might do unit-testing if you're using
<a href="https://github.com/angular-ui/ui-router">ui-router</a>. Your experience may vary
with other libraries.</p>
<h3 id="separate-routing-from-the-rest-of-your-configuration">Separate routing from the rest of your configuration</h3>
<p>The key concept in unit testing anything is making it independently testable and
ui-router configuration is no exception.</p>
<p>To do this, you should first extract anything related to ui-router into a
separate module, then require that in your main app module. It's a simple
refactoring that gives immediate benefits even
without the tests - in my experience, ui-router can drown out everything else
in the configuration phase. This makes it easy to see at a glance the high-level
logic of your app, makes the rest of your modules easier to test (you don't have
to bootstrap the entire routing if you don't want to).</p>
<p>I feel including ui-router as a dependency in the routing submodule is also wise
as it keeps the implementation details hidden. In theory, you could replace
ui-router with a different routing library in the future and there would be less to change.
It would look something like this:</p>
<pre><code class="hljs language-js"><span class="hljs-comment">// routing.js</span>
angular.<span class="hljs-title function_">module</span>(<span class="hljs-string">'someApp.routing'</span>, [<span class="hljs-string">'ui.router'</span>])
  .<span class="hljs-title function_">config</span>(<span class="hljs-keyword">function</span>(<span class="hljs-params">$stateProvider, ...</span>){
    ...
  });
</code></pre>
<pre><code class="hljs language-js"><span class="hljs-comment">// app.js</span>
angular.<span class="hljs-title function_">module</span>(<span class="hljs-string">'someApp'</span>, [<span class="hljs-string">'someApp.routing'</span>, ...])
  ...
</code></pre>
<h3 id="helpful-utilities">Helpful utilities</h3>
<p>Here's handful of key utilities that we'll be using to streamline our unit tests.
You'll find these scattered about in the examples below.</p>
<ul>
<li>
<p><code>mockTemplate(url, [template])</code></p>
<p>Since ui-router will by default try to retrieve your views, we use
this tiny function to mock a template for a specific route.</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">mockTemplate</span>(<span class="hljs-params">templateRoute, tmpl</span>) {
  $templateCache.<span class="hljs-title function_">put</span>(templateRoute, tmpl || templateRoute);
}
</code></pre>
</li>
<li>
<p><code>goTo(url)</code></p>
<p>Literally takes you to the specified URL and then does a $digest.
Simply to make tests look more readable.</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">goTo</span>(<span class="hljs-params">url</span>) {
  $location.<span class="hljs-title function_">url</span>(url);
  $rootScope.$digest();
}
</code></pre>
</li>
<li>
<p><code>goFrom(url).toState(state, [params])</code></p>
<p>This is used mainly to check <code>onEnter</code> and <code>onExit</code> blocks, as you
actually need to do the state transition. We prime the <code>$location</code>
so that the ui-router does not immediately go somewhere different on
<code>$scope.$digest()</code>.</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">goFrom</span>(<span class="hljs-params">url</span>) {
  <span class="hljs-keyword">return</span> {<span class="hljs-attr">toState</span>: <span class="hljs-keyword">function</span> (<span class="hljs-params">state, params</span>) {
    $location.<span class="hljs-title function_">replace</span>().<span class="hljs-title function_">url</span>(url); <span class="hljs-comment">//Don't actually trigger a reload</span>
    $state.<span class="hljs-title function_">go</span>(state, params);
    $rootScope.$digest();
  }};
}
</code></pre>
</li>
<li>
<p><code>resolve(value).forStateAndView(state, [view])</code></p>
<p>Resolve blocks are a bit tricky to test, so this is what I've been
using personally. It's a bit weird, but it essentially lets you execute
the resolve as if you were ui-router. It uses <code>$injector</code> to get you the
fully wired up version of the resolve result.</p>
<pre><code class="hljs language-js"><span class="hljs-keyword">function</span> <span class="hljs-title function_">resolve</span>(<span class="hljs-params">value</span>) {
  <span class="hljs-keyword">return</span> {<span class="hljs-attr">forStateAndView</span>: <span class="hljs-keyword">function</span> (<span class="hljs-params">state, view</span>) {
    <span class="hljs-keyword">var</span> viewDefinition = view ? $state.<span class="hljs-title function_">get</span>(state).<span class="hljs-property">views</span>[view] : $state.<span class="hljs-title function_">get</span>(state);
    <span class="hljs-keyword">return</span> $injector.<span class="hljs-title function_">invoke</span>(viewDefinition.<span class="hljs-property">resolve</span>[value]);
  }};
}
</code></pre>
</li>
</ul>
<h3 id="url-routing">URL routing</h3>
<p>One of the most important things to check is whether your routing matches
your expected state transitions. This is where you test all your
<code>$urlRouterProvider</code> <code>.when()</code>, <code>.rule()</code> and <code>.otherwise()</code> blocks.
This is also where you can check whether your state url mappings are what
you expect them to be.</p>
<p>Since actions speak louder than words, here's an example.
Say you have the following configuration:</p>
<pre><code class="hljs language-js">...
.<span class="hljs-title function_">config</span>(<span class="hljs-keyword">function</span> (<span class="hljs-params">$urlRouterProvider, $stateProvider</span>) {
  $urlRouterProvider
    .<span class="hljs-title function_">when</span>(<span class="hljs-string">''</span>, <span class="hljs-string">'/home'</span>)
    .<span class="hljs-title function_">when</span>(<span class="hljs-string">'/'</span>, <span class="hljs-string">'/home'</span>)
    .<span class="hljs-title function_">otherwise</span>(<span class="hljs-keyword">function</span> (<span class="hljs-params">$injector</span>) {
      $injector.<span class="hljs-title function_">get</span>(<span class="hljs-string">'$state'</span>).<span class="hljs-title function_">go</span>(<span class="hljs-string">'404'</span>, {}, { <span class="hljs-attr">location</span>: <span class="hljs-literal">false</span> });
    });

  $stateProvider
    .<span class="hljs-title function_">state</span>(<span class="hljs-string">'home'</span>, {
      <span class="hljs-attr">url</span>: <span class="hljs-string">'/home'</span>,
      <span class="hljs-attr">templateUrl</span>: <span class="hljs-string">'views/home.html'</span>
    })
    .<span class="hljs-title function_">state</span>(<span class="hljs-string">'404'</span>, {
      <span class="hljs-attr">templateUrl</span>: <span class="hljs-string">'views/404.html'</span>
    });
});
</code></pre>
<p>The test structure for URL routing would then look something like this:</p>
<pre><code class="hljs language-js"><span class="hljs-title function_">describe</span>(<span class="hljs-string">'path'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
  <span class="hljs-title function_">describe</span>(<span class="hljs-string">'when empty'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
    <span class="hljs-title function_">beforeEach</span>(mockTemplate.<span class="hljs-title function_">bind</span>(<span class="hljs-literal">null</span>, <span class="hljs-string">'views/home.html'</span>));
    <span class="hljs-title function_">it</span>(<span class="hljs-string">'should go to the home state'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
      <span class="hljs-title function_">goTo</span>(<span class="hljs-string">''</span>);
      <span class="hljs-title function_">expect</span>($state.<span class="hljs-property">current</span>.<span class="hljs-property">name</span>).<span class="hljs-title function_">toEqual</span>(<span class="hljs-string">'home'</span>);
    });
  });
  <span class="hljs-title function_">describe</span>(<span class="hljs-string">'/'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
    <span class="hljs-title function_">beforeEach</span>(mockTemplate.<span class="hljs-title function_">bind</span>(<span class="hljs-literal">null</span>, <span class="hljs-string">'views/home.html'</span>));
    <span class="hljs-title function_">it</span>(<span class="hljs-string">'should go to the home state'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
      <span class="hljs-title function_">goTo</span>(<span class="hljs-string">'/'</span>);
      <span class="hljs-title function_">expect</span>($state.<span class="hljs-property">current</span>.<span class="hljs-property">name</span>).<span class="hljs-title function_">toEqual</span>(<span class="hljs-string">'home'</span>);
    });
  });
  <span class="hljs-title function_">describe</span>(<span class="hljs-string">'/home'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
    <span class="hljs-title function_">beforeEach</span>(mockTemplate.<span class="hljs-title function_">bind</span>(<span class="hljs-literal">null</span>, <span class="hljs-string">'views/home.html'</span>));
    <span class="hljs-title function_">it</span>(<span class="hljs-string">'should go to the home state'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
      <span class="hljs-title function_">goTo</span>(<span class="hljs-string">'/home'</span>);
      <span class="hljs-title function_">expect</span>($state.<span class="hljs-property">current</span>.<span class="hljs-property">name</span>).<span class="hljs-title function_">toEqual</span>(<span class="hljs-string">'home'</span>);
    });
  });
  <span class="hljs-title function_">describe</span>(<span class="hljs-string">'otherwise'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
    <span class="hljs-title function_">beforeEach</span>(mockTemplate.<span class="hljs-title function_">bind</span>(<span class="hljs-literal">null</span>, <span class="hljs-string">'views/404.html'</span>));
    <span class="hljs-title function_">it</span>(<span class="hljs-string">'should go to the 404 state'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
      <span class="hljs-title function_">goTo</span>(<span class="hljs-string">'someNonExistentUrl'</span>);
      <span class="hljs-title function_">expect</span>($state.<span class="hljs-property">current</span>.<span class="hljs-property">name</span>).<span class="hljs-title function_">toEqual</span>(<span class="hljs-string">'404'</span>);
    });
    <span class="hljs-title function_">it</span>(<span class="hljs-string">'should not change the url'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
      <span class="hljs-keyword">var</span> badUrl = <span class="hljs-string">'/someNonExistentUrl'</span>;
      <span class="hljs-title function_">goTo</span>(badUrl);
      <span class="hljs-title function_">expect</span>($location.<span class="hljs-title function_">url</span>()).<span class="hljs-title function_">toEqual</span>(badUrl);
    });

</code></pre>
<p>We use <code>$state.current.name</code> to check whether the transition happened
as we had expected it to. Since we have access to the current state, we could
do a more elaborate expectation here if necessary.</p>
<p>The tests themselves are arguably clear, concise and easy to read. I use
the <code>beforeEach</code> statements liberally because they make it easy to add new
tiny micro-tests for any other behavior I want to verify.</p>
<p>As a bonus, we implicitly check whether the correct view is being loaded.
If this is unwanted, you could mock out <code>$templateCache</code> to always return
whatever the argument was. I could see that being useful if your views have
a ton of views that make it cumbersome to always mock them out explicitly.</p>
<p>You can use this pattern to test pretty much anything to do with URL mapping,
including any state parameters, <code>.rule()</code> blocks and such. As they say, sky's
the limit here.</p>
<h3 id="resolve">Resolve</h3>
<p>People usually mock collaborators out in their controller tests. Ui-router
makes this especially easy with the <code>resolve</code> mechanic. However, this often
leaves a gaping hole in test coverage, where you verify whether the controller
acts correctly given the correct dependencies BUT never check whether the correct
dependencies are in fact given.</p>
<p>Here's an example of how to retrieve and test the resolve blocks for a state:</p>
<pre><code class="hljs language-js">$stateProvider
  .<span class="hljs-title function_">state</span>(<span class="hljs-string">'stateWithoutViews'</span>, {
    <span class="hljs-attr">resolve</span>: {
      <span class="hljs-attr">someModel</span>: [<span class="hljs-string">'someRepository'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params">someRepository</span>) {
        <span class="hljs-keyword">return</span> someRepository.<span class="hljs-title function_">getModel</span>();
      }],
      ...
    },
    ...
  })
  .<span class="hljs-title function_">state</span>(<span class="hljs-string">'stateWithViews'</span>, {
    <span class="hljs-attr">views</span>: { <span class="hljs-string">'main@layout'</span>: {
      <span class="hljs-attr">resolve</span>: {
        <span class="hljs-attr">otherModel</span>:[<span class="hljs-string">'otherRepository'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params">otherRepository</span>) {
          <span class="hljs-keyword">return</span> otherRepository.<span class="hljs-title function_">getModel</span>();
        }]
      },
      ...
    }},
    ...
  });
</code></pre>
<pre><code class="hljs language-js"><span class="hljs-title function_">describe</span>(<span class="hljs-string">'state'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
  <span class="hljs-title function_">describe</span>(<span class="hljs-string">'stateWithoutViews'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
    <span class="hljs-title function_">it</span>(<span class="hljs-string">'should resolve someModel'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
      <span class="hljs-keyword">var</span> onResolved = sinon.<span class="hljs-title function_">spy</span>(); <span class="hljs-comment">// just a spy of any sort</span>
      mockSomeRepository.<span class="hljs-property">getModel</span>.<span class="hljs-title function_">returns</span>($q.<span class="hljs-title function_">when</span>(<span class="hljs-string">'something'</span>)); <span class="hljs-comment">// just a mock for the service</span>
      <span class="hljs-title function_">resolve</span>(<span class="hljs-string">'someModel'</span>).<span class="hljs-title function_">forStateAndView</span>(<span class="hljs-string">'stateWithoutViews'</span>)().<span class="hljs-title function_">then</span>(onResolved);
      $rootScope.$digest();
      <span class="hljs-title function_">expect</span>(onResolved).<span class="hljs-title function_">toHaveBeenCalledWith</span>(<span class="hljs-string">'something'</span>);
    });
  });
  <span class="hljs-title function_">describe</span>(<span class="hljs-string">'stateWithViews'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
    <span class="hljs-title function_">it</span>(<span class="hljs-string">'should resolve otherModel'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
      <span class="hljs-keyword">var</span> onResolved = sinon.<span class="hljs-title function_">spy</span>(); <span class="hljs-comment">// just a spy of any sort</span>
      mockOtherRepository.<span class="hljs-property">getModel</span>.<span class="hljs-title function_">returns</span>($q.<span class="hljs-title function_">when</span>(<span class="hljs-string">'other'</span>)); <span class="hljs-comment">// just a mock for the service</span>
      <span class="hljs-title function_">resolve</span>(<span class="hljs-string">'otherModel'</span>).<span class="hljs-title function_">forStateAndView</span>(<span class="hljs-string">'stateWithViews'</span>, <span class="hljs-string">'main@layout'</span>)().<span class="hljs-title function_">then</span>(onResolved);
      $rootScope.$digest();
      <span class="hljs-title function_">expect</span>(onResolved).<span class="hljs-title function_">toHaveBeenCalledWith</span>(<span class="hljs-string">'other'</span>);

<p><code>resolve(value).forStateAndView(state, [view])</code> is used to retrieve the resolved value,
which in these cases were functions that returned promises.</p>
<p>As you can see, you can mock out any collaborators and test any scenarios as you wish.
You can even add new <code>$stateParams</code> and check any permutations there.</p>
<h3 id="onenter-and-onexit"><code>onEnter</code> and <code>onExit</code></h3>
<p>These are pretty much straightforward - just force a transition to the state you
wish to test (and then out of it, for <code>onExit</code>). So, something like this:</p>
<pre><code class="hljs language-js"><span class="hljs-title function_">describe</span>(<span class="hljs-string">'onEnter'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
  <span class="hljs-title function_">it</span>(<span class="hljs-string">'should open a modal'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params"></span>) {
    <span class="hljs-title function_">goFrom</span>(<span class="hljs-string">'/modalState'</span>).<span class="hljs-title function_">toState</span>(<span class="hljs-string">'modal'</span>);
    <span class="hljs-title function_">expect</span>(mockModal.<span class="hljs-property">open</span>).<span class="hljs-title function_">toHaveBeenCalled</span>();
  });
});

<h3 id="statechange-events"><code>$stateChange*</code> events</h3>
<p>Admittedly, these are a bit tricky to test. On the one hand, you could simply
<code>$emit</code> the desired event, but then you're bypassing ui-router completely, so
there may be situations where that hides a bug somewhere.</p>
<p>On the other hand, you could just do a state transition (successful or failed)
and then simply verify any side effects. The problem here is that you're being
a bit too indirect and the state transition itself might interfere with the
properties you want to test. So, for example, to test a <code>$stateChangeError</code>
handler you might mock one of your state resolves to throw an error.</p>
<p>The exact situation depends on your use case, but either way, there are some
drawbacks to either approach. At this point, I'm leaning towards the first
one if you create a simple utility to hide the details of the event itself.</p>
<h3 id="other-notes">Other notes</h3>
<ul>
<li>
<p>You can test state transition chains by listening in on the
<code>$stateChangeSuccess</code> event:</p>
<pre><code class="hljs language-js"><span class="hljs-title function_">it</span>(<span class="hljs-string">'should visit multiple states'</span>, <span class="hljs-keyword">function</span>(<span class="hljs-params"></span>){
  <span class="hljs-keyword">var</span> statesVisited = [];
  $rootScope.$on(<span class="hljs-string">'$stateChangeSuccess'</span>, <span class="hljs-keyword">function</span> (<span class="hljs-params">event, toState</span>) {
    statesVisited.<span class="hljs-title function_">push</span>(toState.<span class="hljs-property">name</span>);
  });
  <span class="hljs-title function_">goTo</span>(<span class="hljs-string">'/someUrl'</span>);
  <span class="hljs-title function_">expect</span>(statesVisited).<span class="hljs-title function_">toEqual</span>([<span class="hljs-string">'state1'</span>, <span class="hljs-string">'state2'</span>]);
});
</code></pre>
</li>
<li>
<p>Utilize <code>beforeEach()</code>. Your state configuration is usually a fairly complex tree
structure. Correctly using these methods lets you defer common details closer to the
<code>describe()</code> statement, so the preconditions are the same for any child
tests. This keeps the test code itself clean and succinct.</p>
</li>
<li>
<p>There are many more things you can test, such as whether the correct controllers are specified,
state data fields, <code>$stateParams</code> parsing and such. Really, everything depends on your
use case and what you deem most important. Pretty much everything about the ui-router
configuration is accessible in one way or another, which makes testing it just a case
of letting your imagination run wild.</p>
</li>
</ul>
<h3 id="summary">Summary</h3>
<p>You can and should unit test your routing configuration if you're using ui-router.
I've personally found a couple of hidden bugs in my apps while researching how
to best approach this. The tests not only verify functionality is correct, but
also serve as a high-level overview of your application routing.</p>
